## §3 实例化：RAG 系统（朴素 RAG / HyDE / 重排 / GraphRAG）

`(1)–(6)` 拆解：

```
（1）文档加载与切分       → 讲 chunk_size、overlap、句子/语义切分取舍
（2）Embedding 与索引     → 讲模型选择、向量库（FAISS / Chroma / 内存）
（3）检索器               → 讲 TopK、分数阈值、是否带 metadata 过滤
（4）重排（可选）          → 讲 cross-encoder vs 启发式 vs LLM 重排
（5）生成器               → 讲 prompt 拼接、引用标记、上下文截断
（6）运行实例与分析        → 贴 stdout，看召回质量与最终答案
```

骨架开篇（朴素 RAG 示例）：

```markdown
## 5.1 朴素 RAG（Naive RAG）

在上一章我们用 ReAct 让模型主动调用搜索工具，让它能"现查现答"。然而搜索引擎的结果质量参差不齐，且没法回答**关于私有文档库**的问题。本节我们将聚焦于另一种经典方案 —— **朴素 RAG (Naive Retrieval-Augmented Generation)**：先把私有文档切碎、做向量索引，让模型在回答前先"翻一翻自己的笔记本"。

### 5.1.1 朴素 RAG 的工作原理

在 RAG 诞生之前，让模型回答私有知识有两种典型做法：一类是**纯微调**，把知识塞进模型权重，但成本高且无法热更新；另一类是**长上下文塞所有文档**，但成本爆炸且模型容易"遗忘"中段内容。

朴素 RAG 的巧妙之处在于：**把"记忆"放在模型外部**。如果说微调像把书背下来，那么 RAG 更像考前抱临时书翻一翻——题目来了再去查最相关的几页。

为此，朴素 RAG 通过两阶段流程：

- **离线阶段**：文档切分 (Chunking) → 向量化 (Embedding) → 写入索引
- **在线阶段**：query 向量化 → 相似度召回 (Retrieval) → 拼进 prompt → 生成

我们可以将检索这一步形式化。给定 query $q$ 和文档库 $\mathcal{D}$，每个文档 $d \in \mathcal{D}$ 的相关性打分为：

$$\text{score}(q, d) = \cos(\mathbf{e}_q, \mathbf{e}_d)$$

召回集 $D_q = \text{TopK}(\{\text{score}(q, d) : d \in \mathcal{D}\}, k)$，最终生成依赖 $q$ 与 $D_q$：$a = \text{LLM}(q, D_q)$。

适用场景：

- **企业知识库问答**：例如内部 Wiki / 产品手册的智能客服
- **文档比较与摘要**：例如同一份合同新旧版本对比
- **代码库搜索**：例如根据自然语言找到相关函数实现

因此我们将构建一个能回答 `multi-agent` 仓库内问题的 RAG 系统。例如："本仓库的 ReAct 实现是怎么处理解析失败的？"
```

在上一节的朴素 RAG 中，模型只能回忆**写在外部文档里**的事实。然而在多轮对话或长时任务中，智能体还需要回忆**自己上一轮做过什么、犯过什么错**。本节我们将聚焦于 **反思型记忆 (Reflective Memory)**：让智能体把自己每一轮的"行动 + 反思"都写下来，下一轮主动翻看。

在反思型记忆诞生之前，多轮 Agent 通常用两种机制保留上下文：一类是**全量 scratchpad**，把所有 Thought / Action / Observation 拼进下一轮 prompt，简单但 token 爆炸；另一类是**滑动窗口**，只保留最近 N 轮，简单但会"失忆"。

## §7 段首注释编号模板（文档与代码双向呼应）

文档里的 `（1）（2）（3）` 与代码里的 `# 1) # 2) # 3)` 必须严格对应。Agent 主循环示例：

```python
def run(self, question: str):
    self.history = []
    for step in range(self.max_steps):
        # 1) 格式化提示词（详见教程 4.X.3 (1)）
        prompt = ...

        # 2) 调用 LLM 进行思考
        response_text = self.llm_client.think(...)

        # 3) 解析 Thought / Action（对应 4.X.3 (3) 的解析器）
        thought, action = self._parse_output(response_text)

        # 4) 执行 Action：要么 Finish 收尾，要么调用工具
        if action.startswith("Finish"):
            return ...
        observation = self._call_tool(action)

        # 5) 闭环：把本轮 Action / Observation 追加进 history
        #    没有这一步，下一轮 LLM 看不到"上一步发生了什么"
        self.history.append(f"Action: {action}")
        self.history.append(f"Observation: {observation}")
```

RAG 检索器示例：

```python
def retrieve(self, query: str, k: int = 5) -> list[Chunk]:
    # 1) query 编码（必须用与索引相同的 embedding 模型）
    q_vec = self.embedder.encode(query)

    # 2) 余弦相似度 TopK 召回
    scored = [(cosine(q_vec, c.vec), c) for c in self.chunks]
    topk = sorted(scored, reverse=True)[:k]

    # 3) 阈值过滤：分数过低的当作"未召回"
    return [c for s, c in topk if s >= self.threshold]
```
